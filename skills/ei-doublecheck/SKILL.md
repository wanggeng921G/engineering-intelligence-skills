# Engineering doublecheck

Extract the few claims that drive the user's decision. Check internal consistency, arithmetic and units, version/part/revision specificity, citation fit, and whether the conclusion exceeds the evidence. Seek one plausible failure mode. Correct errors before delivery.

Escalate a disputed or consequential fact to `ei-fact-check`. If a check cannot be done, identify it and lower confidence. Do not append a ritual report to trivial code or casual replies. Do not claim an unrun check passed.
