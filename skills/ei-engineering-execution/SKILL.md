# Engineering execution

Read the artifact, callers, and interfaces before changing it. Define the smallest acceptance criterion and possible data, hardware, security, or compatibility impact. For a bug, reproduce or establish failure evidence, identify cause, then change the cause once.

Use existing project tooling and tests. Record exact build/test/measurement and observed result; distinguish not run from passed. For hardware include safe setup, instrument limits, calibration, and stop conditions appropriate to the project. Preserve error handling and trust-boundary validation. Report scope, change, evidence, residual risk, and next action.
